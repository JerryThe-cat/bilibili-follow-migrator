B站关注迁移助手（A → B）v1.0.0

用途
把自己 A 账号的 UP 主关注名单复制到自己 B 账号，跳过 B 已关注的人和 B 自己。
只新增关注，不取关，不迁移分组、原关注时间、老粉/契约身份。
不需要桌面客户端，也不需要手动复制 Cookie。需要浏览器里的 Tampermonkey（篡改猴）扩展。

一、安装（推荐在你常用的 Chrome / Edge 中）
1. 打开 https://www.tampermonkey.net/ ，选择你的浏览器，通过对应的官方扩展商店安装。
2. Chrome / Edge 若提示未允许脚本运行，打开浏览器的“扩展程序”→ Tampermonkey →“详情”，开启“允许用户脚本”。旧版浏览器可按扩展提示开启开发者模式。
   官方说明：https://www.tampermonkey.net/faq.php?locale=en&q=Q209
3. 打开 https://jerrythe-cat.github.io/bilibili-follow-migrator/ ，点击“复制完整脚本”。
   离线使用也可打开同文件夹的“安装助手.html”。
   也可用文本编辑器打开 bilibili-follow-migrator.user.js，全选并复制文件全部内容。
4. 点浏览器工具栏的 Tampermonkey 图标 →“添加新脚本”/“创建新脚本”。
5. 删除编辑器内的默认模板，粘贴完整脚本，按 Command+S 保存。
6. 打开 https://www.bilibili.com/ 并刷新，右下角会出现“关注迁移 A → B”。
   脚本只在 www.bilibili.com 上运行。空间页面 space.bilibili.com 没有入口是正常的，请回到首页操作。

二、从 A 导出
1. 登录 A 账号，刷新 B站首页。
2. 点右下角“关注迁移 A → B”，点“识别账号”，核对名字与 UID。
3. 点“读取并导出 A 的全部关注”。
4. 等待读取与完整性检查，浏览器会下载 B站关注_A-你的UID_日期.json。
   只有人数、分页及前后总数一致才导出。读取期间不要手动改变关注列表。
5. 保留此 JSON。它是名单备份，不含密码和 Cookie。

三、在 B 预览并迁移
1. 在 B站退出 A，登录 B，刷新首页。不要在任务运行中切换账号。
2. 打开迁移面板，点“识别账号”，核对确实是 B。
3. 点“选择 A 的名单”，选刚下载的 JSON。
4. 点“比对 B，生成待迁移名单”。这一步只读取，不会执行关注。
5. 检查 A → B 的账号与 UID、人数，展开“查看名单”。B 已关注的人标为跳过；名单里的 B 本人也会跳过。
   面板最多显示前 200 条，完整名单可用“导出进度报告”查看。
6. 默认每次关注等待 8–10 秒（可设置基础间隔 5–120 秒，再随机加 0–2 秒）。
7. 点“开始 / 继续”，助手会重新读取 B 的完整关注名单，再弹出本次人数及目标账号确认框。
8. 确认后开始。请保持页面打开。每个请求之前还会检查目标账号。
9. 本轮结束后自动重新读取 B 的关注列表核对。只有确实存在于 B 列表中的 UP 才视为核对通过。

四、暂停、刷新和续传
- 点“暂停”：不再发送下一条请求。已发出的请求不能撤回，会等它返回/超时后记录结果。
- 每个人的处理进度都保存到本浏览器 Tampermonkey 的脚本存储中。
- 关闭、刷新浏览器或电脑重启不会自动恢复执行；重新登录 B，打开首页，点“开始 / 继续”。
- 续传会重新比对 B 已关注的名单，即使上次请求实际成功但响应丢失，也会跳过，不盲目重复发送。
- 续传不需要再次导入或点击“生成待迁移名单”，否则会替换原任务记录。
- 换浏览器、卸载脚本/扩展或清除扩展数据会丢失进度。此时可用 A 的原始 JSON 重新生成任务，重新比对后继续缺少的部分。
- 只允许同一浏览器内、同一站点的一个标签页执行本助手任务。不要在多个浏览器同时运行。

五、失败重试与核对
- “开始 / 继续”处理待迁移项；“重试失败项”处理待迁移项及失败项。
- 重试前会重新比对 B，已经关注成功的会自动跳过。
- 普通失败会记录具体错误，继续处理其他人；连续失败 3 人就停止。
- 风控、登录变化、关注数量上限、网络超时等情况会直接停止整轮；不会在后台不断重试。
- “核对迁移结果”只读取 B，不会新增或取消关注。缺失的人会标为失败/未核实，可再手动重试。
- “导出进度报告”保存完整名单、状态、错误及尝试次数，不含 Cookie；报告不是 A 名单文件，不用于导入。
- 迁移结束可点“清除本地任务”，只清除进度，不影响账号的任何关注。

六、常见问题
没有入口：确认在 https://www.bilibili.com/ 首页，扩展和脚本均启用，允许用户脚本执行，并刷新网页。
导出不完整：可能是接口限制、列表正在变化或分页异常。脚本不会将部分名单伪装成完整备份；稍后重新读取。
HTTP 412/429、-352 等：暂时停止迁移，等待平台恢复，再手动续传。固定间隔无法保证不会触发平台限制。
UID 很长：以字符串保存，支持长 UID。文件中已经丢失精度的数字会拒绝导入，而不是猜测修复。
B 已经有很多关注：会完整读取后去重；触及平台关注上限会暂停并显示错误。
隐私：仅请求 api.bilibili.com；名单与进度保存在本地。脚本不包含第三方统计和外部依赖。

七、验证范围
已完成核心逻辑的自动测试和使用模拟接口的隔离浏览器测试。
模拟测试不等于真实 B站接口联调；没有使用你的账号发送任何关注请求。
B站接口或浏览器扩展策略可能变化；若遇到错误，请提供面板错误文字，不要提供 Cookie。
